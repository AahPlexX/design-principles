Level 5, Lesson 4: Layout density in data-dense UI

A finance team wants a transaction ledger that shows all 40 rows on one screen, with no scrolling. The current design uses the same roomy 24px row padding as the rest of the product's marketing pages, so only 14 rows fit before the screen runs out.

Which spacing choice fits the finance team's goal, and why isn't it a design mistake?

Density is how much content fits into a given area, and how tight or generous a layout's spacing should be depends on the job it's doing. A marketing page wants breathing room because it's showing very little content and wants to feel calm; a 40-row ledger wants density because the person using it needs to compare many rows at a glance without constant scrolling. Tight spacing in a data-dense tool isn't corner cutting — it's the right tradeoff for a task where scanning a lot of rows at once matters more than an airy feel.
