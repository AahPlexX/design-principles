Level 2, Lesson 5: Sharing one rhythm between spacing scale and type scale

A two-column article splits a long feature into two blocks of body text. The spacing scale is built on multiples of 8px, but nobody checked the type scale against it — the body copy's line-height comes out to an odd 23px. Scroll down the page and the two columns' lines slowly drift out of step with each other, even though every individual paragraph looks fine on its own.

A page's spacing scale is built on multiples of 8px (8, 16, 24, 32...). A paragraph is set with font-size: 16px; line-height: 24px;, so each line of text takes up 24px vertically. Why does that particular line-height help the paragraph's text blend into the same rhythm as the whitespace around it?

A spacing scale and a type scale can either share one base unit or run as two disconnected systems, and the difference shows up the moment text sits next to other spaced elements. Here, 24px is 3× the page's 8px base unit, so a paragraph's line-height lands on the exact same grid as every margin and gap built from that scale — the text and the whitespace around it read as one continuous rhythm instead of two things that happen to be near each other. An odd line-height like 23px breaks that: nothing about it aligns with 8, 16, 24, or 32, so the text's own rhythm quietly runs out of sync with the layout's, and a reader feels that misalignment even without being able to name it. This applies to body copy as much as headings, and it matters on-screen exactly as much as in print, since it's the same visual grid either way.
