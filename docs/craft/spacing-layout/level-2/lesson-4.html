Level 2, Lesson 4: rem/px/em for spacing, and why rem respects zoom

A reader with low vision opens their browser's settings and raises the default text size, the way the browser's own accessibility options intend. On one site, the padding around every card grows along with the bigger text, so the layout still looks balanced. On another, the text grows but the padding doesn't move at all — the bigger words start crowding right up against the edge of the box.

A card's padding is set with padding: 1rem;. A reader raises their browser's default font-size setting from 16px to 20px. What happens to that padding, and why?

"rem" stands for root em — one rem always equals the font-size set on the page's root <html> element, which defaults to 16px but is exactly what a reader changes when they raise their browser's text-size preference. Raise that root size to 20px, and every rem-based value on the page — including padding: 1rem — scales up with it, to 20px. em is also relative, but to the current element's own font-size rather than the root's, so nested em values can compound in ways that make them harder to predict for spacing. px is an absolute unit tied to a fixed number of pixels, so it ignores the reader's font-size preference entirely — which is exactly why fixed-px padding stayed put while the text around it grew. That's the practical reason rem is the more common choice for spacing that needs to stay proportioned as text scales.
