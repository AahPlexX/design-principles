Level 6, Lesson 2: Nested padding stacking into an oversized gap

Margin can collapse — two adjacent margins merge into whichever one is bigger. Padding never does that. Every container's padding sits on top of every other container's padding, which is easy to forget once a component ends up nested three or four layers deep.

A card is nested three layers deep:

.page-container { padding: 16px; }
.section-wrapper { padding: 16px; }
.card { padding: 16px; }

On a 320px-wide phone, how much horizontal space actually separates the edge of the screen from the card's own text content?

Padding never collapses the way two adjacent margins can — every nested container's padding adds directly on top of the ones around it. Here, three 16px values in a row (page container, section wrapper, card) total 48px of inset before the card's text even starts, and on a 320px-wide screen that's noticeably more than any single 16px value suggests on its own. box-sizing: border-box changes how a box's own width is calculated — it doesn't stop that box's padding from adding to the padding of the containers around it. The fix isn't deleting all three paddings; it's looking at the total and deciding which single layer should actually own that edge gap at a given screen size.
