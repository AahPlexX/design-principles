Level 6, Lesson 4: Keeping row-gap and column-gap equal at wrap points

The CSS gap property takes two values, one for the space between rows and one for the space between columns. Setting them differently is invisible right up until a layout wraps onto more than one row — then both values are on screen at once, and only one of them was designed on purpose.

A product grid is built like this:

.grid {
  display: flex;
  flex-wrap: wrap;
  gap: 8px 32px; /* row-gap column-gap */
}

On a wide desktop window every card fits on one row, so the mismatched gap never shows. On a phone, the same cards wrap onto three rows. What happens to the grid's visual grouping once it wraps?

gap is shorthand for row-gap then column-gap, and the moment a wrapping layout puts items on more than one row — whether that's flex-wrap or a grid that reflows at a narrower width — both values are visible at the same time. An 8px vs. 32px mismatch is easy to miss when only one of those gaps ever gets seen (a single row on desktop), but once both are on screen together, the smaller gap does the grouping the layout wasn't planning for: rows read as bands instead of every card reading as equally related to its neighbors. Unless there's a specific reason to signal rows and columns differently, keep row-gap and column-gap equal — gap: 24px; instead of gap: 8px 32px; — so a layout doesn't invent a grouping nobody designed once it wraps.
