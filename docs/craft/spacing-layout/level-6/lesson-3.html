Level 6, Lesson 3: Common layout skeletons and their alignment mistakes

Most pages are built from a handful of repeating skeletons: a sidebar next to a content column, a grid of equal-width cards, a single centered reading column. Each one has its own favorite way of quietly slipping out of alignment, even when every individual piece looks fine on its own.

A dashboard uses a sidebar-plus-content skeleton: a 240px sidebar and the main content area are both direct children of the same CSS grid row, so their boxes start at the exact same height. The sidebar's nav list has padding-top: 24px. The main content starts with a plain <h1>, still carrying the browser's default top margin. Why do the sidebar's first link and the page's heading end up sitting at different heights, even though both columns start at the same grid line?

Lining up a column's outer box tells you nothing about where the content inside it starts. Here the sidebar's nav has 24px of its own padding-top, while the h1 still carries whatever top margin the browser applies to headings by default — two unrelated numbers, so the two columns' first lines land at different heights even though the grid itself is perfectly aligned. The fix is to match those numbers on purpose: reset the h1's default margin and give both columns' first line the same offset from the grid line, instead of leaving it to whatever each piece's default happens to be. The same slip shows up in other skeletons too — a card grid where one card's button sits lower because its body text ran one line longer, or a centered column where the heading is optically centered but the paragraph below it is centered by strict math and looks slightly off as a result.
