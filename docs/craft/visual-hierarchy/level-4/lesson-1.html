Level 4, Lesson 1: Two primary actions on one screen breaks the decision

A note-taking app's toolbar puts "New note" and "Export all notes" side by side, both rendered as identical solid-blue buttons at the same size. Nothing in the styling tells a user which one is the everyday action and which one is the occasional one, so on every visit they pause for a beat to reread both labels before clicking either.

Given that toolbar — "New note" and "Export all notes," both solid blue, same size, same weight — what actually fixes the hierarchy problem?

The problem isn't that either button is too small or in the wrong spot — it's that two actions are competing at the exact same visual weight, so nothing signals which one is the default. A screen needs exactly one dominant element for its main action; here that means restyling the rare action (export) down to a lower tier, like an outline or text-only button, while the common action (new note) keeps the loud, filled style. Making both bigger, reordering them, or adding a shared shadow all leave the two actions equally weighted, so the reader still has to stop and read both labels before clicking.
