Level 4, Lesson 2: Primary/secondary/tertiary button tiers

A job application form ends with three different actions in a row: finish and submit, save a draft to finish later, or open the terms of service to read them first. Those three jobs don't deserve the same visual shout. Most design systems solve this with three button tiers instead of one style for every clickable thing: a primary button (a solid, filled background at the screen's highest contrast) for the one action the screen actually wants clicked; a secondary button (usually just an outline or a lighter fill) for a real but lesser alternative; and a tertiary button (plain text, no border or fill) for something optional or rarely needed. The tier isn't decoration — it's a promise about how important the action actually is.

A settings panel has three actions: "Save changes," "Cancel," and "View change history" (a link to a log of past edits). Which tier assignment matches the toolkit above?

"Save changes" is the action this screen exists for, so it earns the primary, filled treatment. "Cancel" is a legitimate but secondary path — someone really might want it — so an outlined button gives it real visual presence without competing with Save for the eye's attention. Viewing change history is optional background reading, not a decision the screen is asking for, so a plain text link is enough. Flattening all three to the same style, or promoting the least important one to the loudest spot, erases the exact distinction button tiers exist to make.
