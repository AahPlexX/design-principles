Level 6, Lesson 4: Hierarchy drift — re-audit after every new addition

A checkout page shipped with one obvious focal point: a large "Place order" button. Over the next six months, three separate teams each added one small element — a countdown timer, a "free shipping" badge, a chat bubble — and each one was reviewed on its own and judged harmless. None of those reviews ever asked what the page looked like with all four elements competing at once.

A checkout page originally had one clear focal point: a large "Place order" button. Over six months, three separate teams each added one small element — a countdown timer, a "free shipping" badge, and a chat bubble — each approved on its own as "not too loud." Six months later the page has five visually competing elements and no clear focal point. What actually went wrong in that process?

None of the three additions was necessarily wrong in isolation — the mistake was reviewing each one against an empty page instead of against the page's current state, including every other recent addition. Hierarchy has to be re-audited as a whole every time something new goes on the page, because the fourth "small, harmless" element can be the one that finally breaks a hierarchy the first three had already been quietly eroding.
