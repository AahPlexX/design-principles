Level 6, Lesson 2: Heading levels as a second, machine-readable hierarchy

A sighted reader figures out a page's structure by scanning font size and boldness. Someone using a screen reader often never sees any of that — instead, many screen readers can pull up a page's headings as their own standalone list, independent of how anything is styled, and jump straight to the one they want. That list is only useful if the heading tags describe where something actually sits in the page's outline, not just which font size happened to look right.

A page's title is marked up as <h1>. The three section headings below it are all marked up as <h3>, because that's the tag whose default font size already matched the design — no <h2> appears anywhere on the page. A screen reader user pulls up the page's list of headings to jump to the section they want. What do they run into?

Heading levels form a second hierarchy that exists independently of how anything looks — a screen reader can announce a page's headings as a navigable outline, letting someone skim or jump straight to a section the way a sighted reader skims by font size. Picking a heading tag because its default font size matches the design, instead of because of where that heading actually sits in the outline (h1 for the page title, h2 for a main section, h3 for a subsection within it), leaves that second hierarchy broken even though the visual hierarchy looks completely fine.
