Level 5, Lesson 1: Forms — label vs. input vs. helper/error hierarchy

Every form field packs three different kinds of text into a small space: the label (what the field is asking for), the value the person typed, and a line of helper or error text underneath. If all three are styled with the same weight and color, a person has to read every word to figure out which one is a routine hint and which one is a validation problem that needs fixing right now.

A signup field is labeled "Password." Underneath the input, gray helper text reads "Must be at least 8 characters." When someone submits a 5-character password, that line is swapped for "Password is too short" — in the exact same gray color, same size, same weight as the helper text it replaced. What's the hierarchy problem?

A helper line and an error line serve completely different purposes — one is a passive hint, the other means "fix this before you can continue" — so they need different visual weight to match. Giving the error its own color (commonly a warning red) and often a small icon makes the state change impossible to miss, instead of asking someone to re-read the same gray text to notice it changed.
