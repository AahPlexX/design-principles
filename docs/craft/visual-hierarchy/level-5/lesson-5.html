Level 5, Lesson 5: Data tables — emphasizing the column or row that matters most

A plain table gives every column the same font weight and every row the same background, as if all of them mattered equally — but a reader almost never scans a table for everything at once. They usually come looking for one column's value. Leaving that column styled identically to the rest means they have to scan across a cluttered row to find it, every single time.

A banking app's transaction table lists Date, Description, Category, Amount, and Balance across 40 rows — every column the same font weight, same text color, no shading on any row. User research shows that people open this table almost entirely to check one thing: their running Balance. What's the hierarchy problem with the table as built?

A table's columns don't all deserve the same visual weight just because they sit in the same row — the column a reader actually scans for should stand out, the same way a dominant headline stands out on any other screen. Giving Balance a bolder weight, a subtle background tint, or right-aligned numerals that make it easy to scan down the column would let people find it without reading Date, Description, and Category first.
