Level 7, Lesson 2: Resizing a browser window vs. testing on a real device

Dragging the edge of a desktop browser window is a fast way to check where a layout wraps or breaks, and it's worth doing constantly while building. But the window is still running on a desktop, with a mouse, a full-size keyboard, and a rendering engine that isn't necessarily the one your visitors' phones use — so it can hide problems that only show up with real touch input on a real device.

A team drags their desktop browser window down to 375px wide to check the mobile layout. A dropdown menu opens when the mouse hovers over its parent link, and at 375px it still opens exactly the same way. They ship it without testing on an actual phone. What will real phone users run into that this test missed?

A narrowed desktop window still has a real mouse pointer behind it, so a hover-triggered menu keeps working there even though the layout looks "mobile-sized." A finger on a touchscreen has no equivalent hover state, so the same menu can end up impossible to open on an actual phone — a gap only a real-device test would catch.

Full explanation: Responsive Design.
