Level 7, Lesson 3: Browser DevTools device emulation: useful, not a substitute for real testing

A browser's built-in device toolbar goes further than resizing a window — it can report a chosen screen size, tell the page it should expect touch input, and throttle the network. That makes it a genuinely useful step up. It still runs on the desktop browser's own rendering engine underneath, so it can't reproduce a different browser engine's quirks, or an underpowered chip's real performance.

A developer opens Chrome's device toolbar, selects a phone preset, and the page renders with no visible problems. On an actual phone, using that phone's own default browser, one section of the page renders with broken spacing. Why might DevTools have missed this?

Device emulation is a simulation layered on top of the desktop browser you already have open — it changes what the page is told about its viewport and input, but the actual rendering still happens in that one engine. A real phone's own default browser can have different engine-level behavior that no amount of emulated screen size will surface.

Full explanation: Responsive Design.
