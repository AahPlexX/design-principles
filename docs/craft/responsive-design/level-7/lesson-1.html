Level 7, Lesson 1: No horizontal scroll at any width from ~320px up

The single fastest way to catch a broken responsive layout is the crudest: shrink the browser down toward the narrowest phone widths still in common use and see whether a sideways scrollbar shows up. If one does, something on the page is wider than its container, and that's a fail regardless of how good the layout looks at any other width.

A pricing page looks correct at 1200px wide. Shrunk to 320px, a horizontal scrollbar appears and the last column of numbers is cut off. Inspecting the page, you find a promotional banner image inside the layout with no width rule of its own — its natural pixel size is simply wider than the phone screen. What's the fix?

An image with no sizing rule renders at its natural pixel dimensions no matter how narrow its container is — that's almost always the actual cause of horizontal scroll. Letting it scale down with its container fixes the overflow directly; hiding the overflow, deleting the content, or shrinking the file size all leave the real problem (a fixed-size element wider than the viewport) untouched.
