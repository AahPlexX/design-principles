Level 4, Lesson 4: Performance cost of shipping desktop-sized images to mobile

Every fix so far in this level protects against something visibly breaking. This one is different — it never breaks anything a reader can see. It just quietly costs them time and data, one oversized file at a time, on exactly the connections that can least afford it.

A hero image is styled with max-width: 100%; height: auto;, so on a phone it displays at 400px wide. The <img> has a single src pointing to one 2400px-wide file with no srcset. What's actually true about this page on a phone?

Downloading happens before rendering, and CSS only controls rendering. The browser fetches whatever file the markup points it to, in full, and only then shrinks it down to fit the space CSS gives it — the extra pixels are thrown away after being paid for. On a slow mobile connection that's wasted time and data for detail nobody can even see, and on many pages that oversized hero image is also the single largest thing on the screen, so it's often what determines how long the page feels like it takes to load. This is exactly the gap srcset and sizes close: they let a phone request a phone-sized file up front instead of downloading a desktop-sized one and discarding the difference.
