Level 4, Lesson 2: srcset/sizes — the right-sized image per viewport

Stopping an image from overflowing its box is only half the job. A photo can display beautifully at 300px wide on a phone screen while the browser still downloads the full 2400px file behind it. srcset and sizes exist to close that gap — letting a phone fetch a phone-sized file instead of a desktop-sized one.

<img srcset="photo-480.jpg 480w, photo-800.jpg 800w, photo-1600.jpg 1600w" sizes="(max-width: 600px) 100vw, 50vw" src="photo-800.jpg" alt="...">
On a 375px-wide phone screen, which file does the browser actually download?

The browser uses sizes to work out how wide the image's display slot will be at the current viewport, then picks the smallest srcset candidate whose actual pixel width covers that slot. Here, below 600px the slot is the full viewport (100vw), so at 375px wide the 480w file is already more than enough — downloading the 1600w file would just waste bytes for no visible gain. The src attribute is only a fallback for browsers that don't understand srcset.
