Level 5, Lesson 3: Responsive navigation patterns — hamburger, priority nav, bottom tabs

A row of ten nav links across the top of a desktop page has nowhere to go on a phone-width screen — there simply isn't room to lay them out side by side anymore. Three common patterns solve this differently: a hamburger menu tucks everything behind one icon; priority nav keeps whatever fits visible and hides the rest behind a "More" button; a bottom tab bar pins a handful of top destinations to the bottom of the screen at all times. Picking between them is about how the nav actually gets used, not which one looks the most modern.

A mobile app has exactly four core destinations — Home, Search, Messages, Profile — and people switch between them constantly throughout every session. The design puts all four behind a hamburger icon in the top corner to keep the screen looking uncluttered. What's the problem with that choice?

A bottom tab bar keeps a small set of frequently-used destinations visible and one tap away at all times, which matches constant switching between them. A hamburger menu trades that visibility for a tidier-looking screen — reasonable when nav is used occasionally, but it adds an extra tap to something this app's users do all the time. Priority nav solves a different problem (more items than fit, ranked by importance); it isn't automatically the better choice just because it's a newer pattern.
