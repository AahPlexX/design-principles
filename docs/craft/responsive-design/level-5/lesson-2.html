Level 5, Lesson 2: Hover states don't reliably exist on touchscreens

A mouse can rest somewhere without clicking, which is what makes "hover" possible in the first place — the pointer sits over an element and the page reacts before anything is pressed. A finger on a touchscreen has no equivalent resting position: it's either not touching the screen at all, or it's already tapping. Anything a design puts behind "hover to reveal" is asking for a state a touch user can't reliably produce.

A settings page has a small info icon next to a toggle. On desktop, hovering the mouse over the icon shows a tooltip explaining what the toggle does — there's no other way to read that explanation. What happens to someone using the exact same page on a touchscreen tablet?

Touch has no in-between "resting over something" state the way a mouse pointer does — a finger is either off the screen or already tapping. A tooltip that only exists on :hover can end up unreachable, or only reachable through inconsistent browser-specific tap behavior, on a touch device. If the information matters, it needs a way to appear that doesn't depend on hovering at all, like tapping the icon or showing the text by default.

Full explanation: Responsive Design.
