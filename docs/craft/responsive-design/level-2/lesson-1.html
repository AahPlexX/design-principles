Level 2, Lesson 1: Swapping fixed pixels for flexible units

A fixed pixel width isn't wrong at the width you tested it at — it's wrong at every other width, and nobody tests every width by hand. The fix isn't a longer list of fixed widths for more devices; it's not hard-coding a number in the first place.

A two-column layout is built like this: 

.layout  { display: flex; }
.sidebar { width: 320px; }
.main    { width: 900px; }

That's 1220px of fixed-width content. On a phone with a 375px-wide viewport, what happens?

A fixed pixel width means exactly that width, no matter how much viewport is actually available. With flex-wrap left at its default (nowrap), the browser keeps both boxes at 320px and 900px and lets the total overflow — the reader gets a horizontal scrollbar on a 375px phone instead of a layout that fits. Swapping to flexible units fixes it: .sidebar { width: 25%; min-width: 200px; } and .main { flex: 1; } let each column shrink and grow with the viewport instead of staying locked at one width.
