Level 2, Lesson 4: Letting the grid decide how many columns fit

A percentage-based float layout and a fluid grid can look identical on one screen and behave completely differently on the next. The float locks in a column count up front; the grid asks how much room each column actually needs and works the count out itself.

A row of product cards is built two ways. 

/* Version A */
.card { width: 25%; float: left; }

/* Version B */
.grid {
  display: grid;
  grid-template-columns:
    repeat(auto-fit, minmax(12rem, 1fr));
  gap: 1rem;
}

The container is 700px wide, and each card needs at least about 190px to show its image and text without cramming. What's the difference between the two versions at this exact width?

width: 25% always produces exactly 4 columns, whatever their content needs — at 700px that's 175px per card, tighter than the ~190px each one needs to breathe. It doesn't overflow, it just cramps. repeat(auto-fit, minmax(12rem, 1fr)) asks a different question: how many 12rem (192px) columns, plus the gaps between them, actually fit in this container? Three 192px columns plus two 1rem gaps add up to 608px — comfortably within 700px — while a fourth column would need 816px, past the container's width. So the grid keeps 3 columns and wraps the 4th card to a new row instead of squeezing it in.
