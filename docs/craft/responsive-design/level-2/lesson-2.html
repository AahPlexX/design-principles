Level 2, Lesson 2: Scaling text with the reader's font-size setting

Not every unit responds to the same things. Some readers raise their browser's default text size above its usual starting point because that's the size they can actually read comfortably. Whether your text grows along with them depends entirely on which unit you reached for — rem and em are relative to a font-size the browser controls; px is not.

A site is styled like this: 

h1           { font-size: 32px; }
.card-title  { font-size: 1.25rem; }

A reader who finds small text hard to read raises their browser's default font size from its usual 16px starting point up to 24px, using a setting in the browser itself. Which of these two elements actually gets bigger because of that change?

rem always means "some multiple of the root element's font-size" — and the root font-size is exactly the number a reader's browser text-size setting changes. Raise that setting and every rem value recalculates automatically, so .card-title grows from 20px to 30px along with it. em behaves the same way, relative to its parent's font-size, as long as nothing further up the tree overrides it with a fixed unit. px is a fixed, absolute unit: the h1 stays at exactly 32px regardless of what the reader changed, which is precisely the problem for anyone who raised that setting because they needed the text bigger.

Full explanation: Responsive Design.
