Level 3, Lesson 4: Container queries — a component responding to its own box

A media query only ever asks one question: how wide is the browser window? That's fine for page-level layout, but it falls apart for a reusable component that can land in more than one spot on the same page — a card in a wide main column, and the same card squeezed into a narrow sidebar. A container query lets the component ask about the size of its own box instead of the whole page.

The same .card component is used in a page's wide main content area and in its narrow sidebar. A stylesheet rule reads @media (min-width: 1200px) { .card { grid-template-columns: 1fr 1fr; } } so the card shows two columns internally. The browser viewport is 1400px wide either way. What actually happens to the card in the sidebar?

A media query evaluates the browser viewport's width, full stop — it has no way to know how much space a specific component has inside its parent. Since the viewport is 1400px wide regardless of where the card sits on the page, the same two-column rule fires for every card, including the one squeezed into the sidebar. A container query (@container) checks the size of the card's own containing element instead, so the sidebar's copy and the main-content copy can each get the layout that actually fits their own box.

Full explanation: Responsive Design.
