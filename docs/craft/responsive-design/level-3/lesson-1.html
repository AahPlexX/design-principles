Level 3, Lesson 1: Picking breakpoints by content, not by device

A new project kicks off and someone opens a spec doc with a "Breakpoints" section already filled in: 375px, 768px, 1440px. It feels like a shortcut — skip the debate, just match what's popular this year. But the layout in front of you doesn't know it's supposed to break at those exact numbers; it only knows when its own content stops fitting.

A team sets breakpoints at 375px, 768px, and 1440px because those match a phone, a tablet, and a laptop. What's wrong with choosing breakpoints this way?

"iPhone, iPad, desktop" isn't a real category system — screen widths are continuous, and new device sizes appear constantly. The right place for a breakpoint is wherever this layout's own content actually starts to break, found by resizing and watching, not by copying a list of device widths.
