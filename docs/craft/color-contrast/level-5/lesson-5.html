Level 5, Lesson 5: A ratio verified in one theme doesn't carry over to the other

Contrast sign-off usually happens once, on whichever theme gets built or reviewed first. Shipping the second theme afterward on the assumption that "the design system already passed contrast" skips the one step that actually proves anything: checking the specific colors the second theme uses.

A component library's contrast is checked and signed off entirely in light mode. Its dark-mode variant isn't a literal color inversion — it uses a separate set of color tokens for text and backgrounds, including a dark-mode error state (a muted red on a dark, red-tinted card). The dark-mode tokens ship without a separate contrast check, on the reasoning that "contrast already passed for this component." What's wrong with that reasoning?

A contrast ratio is proved for one specific pair of colors, not for a component in the abstract. Dark mode here isn't a straightforward inversion of light mode — it's a different set of tokens entirely, so the light-mode sign-off tells you nothing about whether the dark-mode error text actually clears the minimum against its own background. Each theme's color pairs have to be verified on their own.
