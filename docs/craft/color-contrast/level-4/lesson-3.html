Level 4, Lesson 3: Simulating color vision deficiency during design review

Contrast ratio and color-vision simulation test two completely different things. Contrast ratio compares how light or dark two colors are against each other — it has nothing to do with hue. A saturated red and a saturated green can land at nearly the same lightness, so someone with a red-green deficiency can see them as visually identical even though each one individually passes a contrast check against the background. Most browsers' developer tools include a way to render a page as it would look under different color vision deficiencies, and dedicated simulator tools do the same for exported designs. Running that simulation on the real screen — not just checking ratios — is the step that catches this failure before a user does.

A screen's error state uses a saturated red and its success state uses a saturated green, each individually measured at a comfortable contrast ratio against the background. A reviewer calls the pair "accessible" because both pass. What are they missing?

Contrast ratio checks light-versus-dark separation between a color and its background; it says nothing about whether two colors are separable from each other in hue. A saturated red and a saturated green can each individually pass, while still reading as the same color once viewed through a red-green deficiency simulation. Ratio math can't catch that failure — only simulating the actual color vision deficiency reveals it.
