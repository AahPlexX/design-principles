Level 8, Lesson 4: A disabled button that reads as "just faint" instead of "unavailable"

A disabled control is usually let off the hook on contrast, on the assumption that a user can already tell it's off some other way. That assumption only holds if "some other way" actually exists — if dimming the color is the only change, a disabled button and a quiet, still-clickable one can look identical.

A "Submit" button dims to a soft gray, at roughly 3:1 label contrast, whenever a required field is empty. Nothing else about it changes: same shape, same cursor on hover, no lock icon, no helper text. A designer defends it by saying disabled buttons aren't held to the text contrast minimum, so it's fine. What's the flaw in that defense?

Disabled controls get more contrast latitude because a user isn't meant to be straining to read them — they're not supposed to be interacted with at all, and that should already be obvious. If the only cue is "a bit lighter than the active version," people can't tell the difference between disabled and deliberately subtle, and they'll keep clicking. Pair the dimmed color with a real state change: a different cursor, a tooltip explaining what's missing, or copy that names the blocking condition.
