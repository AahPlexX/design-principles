Level 3, Lesson 2: Input borders have their own minimum

A text field's border isn't decoration — it's the answer to "where does this box start and end, and is there room to type here?" Placeholder text and labels tell a user what to type; only the border (or a fill change standing in for one) tells them where the clickable, typeable area actually is. That's a boundary a user needs to see before they've interacted with anything.

A signup form's text inputs have a label above each field and placeholder text inside, but the field's own border is a barely-there #e8e8e8 line on a white page, with no fill difference and no shadow. A designer argues the label already tells you a field is there, so the border color doesn't matter. What's the problem with that?

A label identifies the field; it doesn't draw its edges. Boundary-defining parts of a UI control — the border of a text input, a checkbox's outline, a card someone can click — need their own contrast against whatever sits right next to them, so the shape reads before anyone has typed, hovered, or focused it. "It becomes visible on focus" doesn't help a user who's still deciding where to click.
