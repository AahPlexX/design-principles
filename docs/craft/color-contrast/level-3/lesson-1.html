Level 3, Lesson 1: Icon-only buttons need contrast too

An icon-only button has no text to fall back on — the icon's shape is the entire interface. If that shape barely stands out from its background, a screen-reader label can announce what the button does, but a sighted user scanning the toolbar still can't find it, or trust their eyes that it's really there. Everything covered so far in this course has been about text. This level is about the parts of an interface that aren't text at all, but still need to be seen.

A file manager's toolbar has three icon-only buttons — rename, download, delete — with no visible labels and no text anywhere nearby. Each icon is drawn in pale gray (#d0d0d0) on a white toolbar. A reviewer says: "the 4.5:1 text rule doesn't apply here, there's no text, so this is fine." Are they right?

Functional, icon-only controls carry meaning the same way a labeled button does — the icon is the only visual cue that the control exists and what it does. That earns it its own contrast minimum against its background, separate from (and generally lower than) the 4.5:1 body-text rule. A screen-reader label fixes the problem for non-sighted users only; a hover tooltip doesn't help someone who hasn't found the button yet, which is exactly the problem pale-gray-on-white creates.
