Level 9, Lesson 3: Color spaces built for predictable steps

Build a five-step tint scale by adjusting lightness in equal numeric jumps in an older color model, and the steps rarely look equal — two shades can look nearly identical while the next jump looks huge. That's because those older models weren't built around how the eye actually perceives brightness. A newer generation of color spaces, OKLCH being one that some designers have started reaching for, is designed so a numeric step tracks more closely with the perceived step. It's an emerging tool for reasoning about color relationships, not an official requirement, and it doesn't replace checking the resulting contrast.

A designer builds a five-shade button scale (default, hover, active, and two disabled states) by moving lightness in equal steps in an older color model. Two of the shades end up looking almost identical on screen, while another step looks jarring. A teammate suggests rebuilding the scale in a perceptually uniform color space like OKLCH instead. What problem would that most likely fix?

The uneven-looking scale happens because equal numeric lightness steps in an older model don't correspond to equal perceived brightness steps. A perceptually uniform space like OKLCH is built so the numbers track perception more closely, which makes a scale like this easier to predict and adjust by eye. It's a genuinely useful way to reason about color relationships — but it's still an emerging approach some designers use, not a settled requirement anywhere, and picking colors in it doesn't skip the step of actually checking the contrast ratio once the shades are chosen.
