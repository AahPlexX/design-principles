Level 2, Lesson 5: Disabled controls are exempt from the ratio, but must still read as disabled

A genuinely disabled control — a "Submit" button that can't be clicked until a form is valid, a field that's locked until an earlier step is finished — is allowed to sit below the normal contrast minimum. The reasoning: nothing in a disabled control is meant to be read or acted on right now, so the readability floor that protects active content doesn't apply to it the same way.

That exemption comes with a catch, though. It only covers controls that are actually disabled — using the real disabled state, not just a clickable button styled to look faint for effect. And even a truly disabled control still needs enough contrast to register as "a real control, currently off," not so little that it looks broken, missing, or like a rendering bug. The bar drops; it doesn't disappear.

A "Submit" button is disabled until the form is valid. While disabled, it has the disabled attribute (so it truly can't be clicked or focused), and its label renders at a low 1.5:1 contrast against the button's background. Once the form becomes valid, the button becomes enabled and jumps to a normal 6:1. Does the disabled state pass?

Because the button uses the real disabled state — not just faded styling on a control a user could still click — it's exempt from the normal contrast minimum while it's off. If it were merely styled to look muted but still clickable, the exemption wouldn't apply: a user could still try to interact with it and needs to be able to read its label at the normal minimum.
