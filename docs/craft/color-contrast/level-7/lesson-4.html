Level 7, Lesson 4: Baking contrast checks into design tokens/CI

A manual check catches a problem once. It won't catch the same problem when someone edits a shared color token six months later and every component using it quietly drifts out of compliance. The fix is to make the computer check automatically, every time, instead of relying on someone remembering to look.

A design system defines a muted-text token at #8a8a8a against a surface token of #ffffff, documented as passing. Six months later, a designer lightens the muted-text token for a cleaner look, without rechecking contrast. Nobody notices until a support ticket comes in about unreadable captions. What fix prevents this from happening again, rather than just patching this one instance?

A one-time check only proves a pair was fine on the day someone looked at it. Wiring the same math into continuous integration — the automated checks that run on every code change — means any token edit that breaks a documented pair fails the build immediately, instead of shipping quietly and waiting for a user to notice.
