About this site

A reference for web design that doesn't assume you already know the vocabulary, and doesn't waste the time of people who do.

Who this is for

Anyone who touches a web page's design: developers who need to make a reasonable call without a designer in the room, designers who want a shared vocabulary with their team, and beginners who want to know why a rule exists, not just that it does.

Every page is written so a first-time reader can follow it start to finish. If you already know the basics, the "Go deeper" section at the bottom of each page has the edge cases and spec details you're actually looking for.

How to read a page

Every principle page has the same six parts, in the same order, on purpose — once you know the shape, you can skim straight to the part you need:

  1. Definition — what the term means, in one sentence.
  2. Why it matters — what actually breaks when you get it wrong.
  3. The core rule — the one thing to remember.
  4. Good vs. bad example — a concrete comparison, not a theory.
  5. Common mistakes — the specific ways people get this wrong in practice.
  6. Checklist — run this against your own work.

Using the exports

This site is the canonical explanation. Two other formats package the same rules for machine use, kept in sync with the site so none of them drift apart:

Skills

/skills holds Claude Code skills — each one turns a principle's checklist into something an agent can run against real code or copy. Copy the folder you want into your own project: 

cp -r skills/design-critique your-project/.claude/skills/

Prompts

/prompts holds standalone system prompts. Each one gives an LLM a persona and a checklist — paste the file's contents in as a system prompt for whatever tool you're using.
