Typography

Typography is the set of decisions that control how easy text is to read: how big it is, how long each line runs, how much space separates lines and paragraphs, and which words stand out as more important than others.

Why it matters

Text is what most of the web actually is. A page can have a striking layout and still fail if the paragraphs are painful to read — lines too long to track, text too small to see comfortably, or no visual difference between a heading and a caption. Readers don't consciously notice good typography; they notice bad typography, as fatigue, and they leave.

The core rule

Keep line length between 45 and 75 characters (about 60 is the sweet spot), keep line height around 1.4–1.6× the font size for body text, and make sure every level of hierarchy (heading, subheading, body, caption) is distinguishable by more than one signal — size and weight, not size alone.

Good vs. bad

Good 
body {
  font-size: 1.125rem;
  line-height: 1.6;
  max-width: 65ch;
}
h1 { font-size: 2.5rem; font-weight: 700; }
h2 { font-size: 1.75rem; font-weight: 700; }

Body text is capped at a readable line length, line height gives text room to breathe, and headings are distinguished by both size and weight.

Bad 
body {
  font-size: 0.9rem;
  line-height: 1.1;
  /* no max-width — text spans
     the full browser window */
}
h1 { font-size: 1.1rem; font-weight: 400; }

Lines run the full width of a wide monitor, text is cramped together, and the heading barely differs from body text — a reader has to work to find the structure.

Common mistakes

  • Letting lines run edge-to-edge on wide screens. Past about 75 characters, the eye loses track of which line to return to when it wraps. Always cap the width of a text block, even on a full-width layout.
  • Using font size as the only signal of hierarchy. A heading that's only slightly bigger than body text, in the same weight, reads as an accident rather than a heading. Pair size changes with weight or color changes.
  • Tight line height on body text. Line height under 1.4 makes lines of text feel like they're touching, which slows reading, especially for longer paragraphs.
  • Centering paragraphs of body text. Centered alignment works for a short headline; for multiple lines, the ragged left edge forces the eye to hunt for where each new line starts.
  • Too many typefaces or weights on one page. More than two typeface families, or more than three weights of one family, usually means the hierarchy is being carried by novelty instead of a clear system.

Checklist

  • Body text line length stays under ~75 characters at any viewport width.
  • Body line height is 1.4–1.6×.
  • Each heading level is distinguishable by more than one property (size + weight, or size + color).
  • Body text is at least 16px (1rem) on mobile — smaller forces zooming.
  • No more than two typeface families are in use.
Go deeper

Modular scales: instead of picking heading sizes by eye, multiply a base size by a fixed ratio (1.25 for a moderate scale, 1.333 or higher for something more dramatic) to get each next size up. This keeps the relationships between sizes consistent as you add more heading levels.

Optical sizing: some variable fonts adjust stroke thickness and spacing automatically as size changes (the font-optical-sizing CSS property), so a heading and a caption of the same family both look correct rather than the caption looking like a shrunk heading.

Fluid type: clamp() lets a font size scale smoothly between a minimum and maximum based on viewport width, e.g. font-size: clamp(1rem, 0.9rem + 0.5vw, 1.25rem), instead of jumping abruptly at breakpoints.
